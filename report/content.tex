\hypertarget{project-objective}{%
\section{Project objective}\label{project-objective}}

My goal is to implement the computational approach in the chapter
\emph{Pooling Strategy for Massive Viral Sequencing} and evaluate it on
viral sequence data. The main idea is to mix several samples into
overlapping pools, sequence those pools, and then assign the sequences
back to their original samples. A successful design should use fewer
pools while keeping the samples distinguishable.

This project connects to the course because finding the minimum number
of valid pools is an NP-hard optimization problem. I am implementing the
chapter's greedy and tabu-search heuristics rather than claiming to find
an optimal solution for every input.

\hypertarget{how-the-implementation-works}{%
\section{How the implementation
works}\label{how-the-implementation-works}}

The compatibility graph represents which samples can be mixed. Each pool
must be a clique, meaning that every pair of samples inside the pool is
compatible. The pool-size limit prevents the algorithm from putting too
many samples together.

GPDA maintains a second graph containing sample pairs that have not yet
been separated. At each step, it adds a pool that separates some of
these pairs. A pair is separated when exactly one of its samples belongs
to the pool. The process continues until every pair has been separated.
An uncovered sample is placed in a singleton pool if necessary, so every
sample has a distinct, nonempty pattern of pool memberships.

The tabu-search procedure looks for a useful clique cut at each greedy
step. It rewards separation of unresolved pairs and penalizes
incompatible pairs inside a candidate pool. The exact solver provides a
reference for checking small clique-cut instances; it does not make the
overall greedy design globally optimal.

For deconvolution, ordinary sequence intersection is not sufficient
because the same sample can contribute different variants to different
pools. The implementation uses kGEM to cluster related sequences. A
generalized intersection keeps clusters with observations from both
pools. Intersections and differences are then used to separate the
individual samples.

\hypertarget{data-and-experimental-setup}{%
\section{Data and experimental
setup}\label{data-and-experimental-setup}}

I first tested the pipeline with a clearly labeled synthetic dataset
containing eight artificial samples and four variants per sample. The
sequences are 306 bases long and were deliberately generated with
well-separated sample populations.

I then used public HCV HVR1 sequences from the dataset associated with
Janiak et al. (2019). I selected the first eight chronic genotype-1
specimen files in numeric identifier order before measuring performance.
These files contain 338 reconstructed haplotype records. I retained all
listed variants and normalized the frequency estimates in their FASTA
headers for sampling. After removing the original gap symbols, I aligned
the sequences together with MAFFT 7.526. The resulting alignment has 180
columns.

For both datasets, I used the following comparison settings:

\begin{itemize}
\tightlist
\item
  Eight samples, with at most four samples per pool.
\item
  All sample pairs assumed compatible for this controlled comparison.
\item
  Eighty observations sampled per included sample per pool.
\item
  Five sampling seeds: 91 through 95.
\item
  Initial clustering multiplier W=2, with retries up to W=4 when a
  recovered sample was empty.
\end{itemize}

The HCV sequences are real, but the pools and read observations are
simulated. I have not performed an experiment using laboratory-pooled
specimens. The public benchmark also does not use measured specimen
titers or epidemiological exclusions.

Every observation received exactly one assignment in these runs.

than reads being left unassigned. Accuracy here measures agreement with
the source labels used to simulate the observations.

The average also hides large differences between specimens. For seed 91,
only 6 of 160 observations from public specimen 80 were correctly
recovered, giving 3.75\% recall. Several other specimens were recovered
completely. Specimen 201 was in a singleton pool, making its recovery
straightforward; this is why I also report recall excluding that
specimen.

\hypertarget{verification-and-implementation-differences}{%
\section{Verification and implementation
differences}\label{verification-and-implementation-differences}}

The saved test run contains \textbf{19 passing tests}. The tests check
pool feasibility, sample separation, the chapter's gain equations, small
exact clique-cut cases, sequence clustering examples, input validation,
source-file checksums, preservation of sequence content through
alignment, and assignment-metric accounting.

There are several differences between executable code and the printed
pseudocode that I have documented rather than treating this as an exact
reproduction:

\begin{itemize}
\tightlist
\item
  The tabu procedure handles nonpositive gains and records only feasible
  cliques. It also has iteration limits and a singleton fallback to
  ensure progress.
\item
  The deconvolution queue replaces both operands with their intersection
  and differences to avoid repeatedly retaining equivalent pool entries.
\item
  The kGEM stopping conditions are interpreted as stopping when
  estimates stabilize, because the printed conditions appear reversed.
  Iterations are bounded.
\item
  Numerical settings, a cap on the number of distinct initial centroids,
  and logarithmic likelihood calculations make the implementation
  executable.
\end{itemize}

The detailed source mapping and explanations are in the main README.
These tests provide evidence of implementation consistency; they do not
prove a global approximation guarantee or validate biological accuracy.

\hypertarget{limitations-and-what-i-learned}{%
\section{Limitations and what I
learned}\label{limitations-and-what-i-learned}}

The main result so far is that success on the synthetic demo does not
carry over to the public HCV subset. The current implementation assigns
some real-sequence populations poorly, even when every recovered sample
is nonempty.

The synthetic and public datasets differ in sequence length, diversity,
variant counts, and frequency distributions. I cannot attribute the
accuracy gap to just one of these factors. The public input consists of
reconstructed haplotypes rather than raw sequencing reads, and the
simulation does not include PCR bias, contamination, titer imbalance, or
sequencing errors. One aligned sequence also occurs in more than one
public specimen, creating ambiguity in sequence identity.

Only eight specimens from one study have been evaluated. Repeating the
sampling with five seeds measures variability for those same specimens,
not performance across independent patient cohorts. Also, four pools
instead of eight individual samples does not by itself demonstrate a
50\% reduction in sequencing costs, since the experiment does not hold
total sequencing depth or laboratory costs fixed.

I have therefore completed an initial implementation and an exploratory
evaluation, but I have not reproduced the chapter's published
experimental accuracy.

\hypertarget{next-steps}{%
\section{Next steps}\label{next-steps}}

My next priority is to understand the incorrect assignments before
adding more features. I plan to:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Trace the generalized intersections where specimens 80 and 142 lose
  correctly assigned observations, using the saved confusion matrices
  and clustering diagnostics.
\item
  Test sequence length, W, sampling depth, and pool-size limits
  separately, keeping the other settings fixed where possible.
\item
  Evaluate additional specimens and datasets using selection rules
  established before inspecting their results.
\item
  Review the documented interpretations of the chapter's pseudocode,
  especially queue refinement and the consensus update, before comparing
  any alternative versions.
\end{enumerate}

These are planned experiments, not completed improvements. I will report
changes in accuracy together with any additional departures from the
chapter.

\hypertarget{reproducing-the-current-work}{%
\section{Reproducing the current
work}\label{reproducing-the-current-work}}

Run these commands from the repository root:

\begin{verbatim}
python3 -m viral_pooling demo
python3 -m viral_pooling.benchmark
python3 -m unittest discover -s tests -v
\end{verbatim}

The committed public alignment allows the comparison to run without
downloading data or installing MAFFT. MAFFT is needed only to regenerate
that alignment.
